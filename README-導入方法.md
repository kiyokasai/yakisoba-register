# 清花祭2026 焼きそば販売レジ

焼きそば **400円/食**、販売目標 **240食**。11/14・11/15の2日間に対応しています。

## 同梱ファイル
- `index.html`：画面
- `style.css`：デザイン
- `app.js`：会計・Firestore同期処理
- `firebase-config.js`：Firebase接続情報（最初は空欄）
- `firestore.rules`：Firestoreアクセス制御ルール

**重要：本番運用前に、最低2台のスマホでテストしてください。** ファイルをアップしただけではFirebaseの接続とスタッフ登録は完了しません。

## 1. Firebaseプロジェクトの作成
1. https://console.firebase.google.com/ を開き、プロジェクトを追加します。名前は例 `kiyokasai-yakisoba-2026`。
2. プロジェクト内で「アプリを追加」→ Web（`</>`）→ ウェブアプリを登録します。Firebase Hostingは不要（Xserverに置きます）。
3. 表示される `firebaseConfig` の `apiKey`, `authDomain`, `projectId`, `appId` をコピーします。
4. このZIP内の `firebase-config.js` をテキストエディタで開き、ダブルクォーテーションの間にそれぞれ貼り付けて保存します。ほかのファイルは原則変更不要です。

## 2. Firestore作成とセキュリティルール
1. Firebaseコンソール → **Firestore Database** → **データベースを作成**。
2. ロケーションはアジア圏を選ぶのが一般的です（作成後の変更に制約があるため確認）。
3. 作成後、「ルール」タブを開きます。
4. `firestore.rules` の内容を **すべて** 貼り付けて **公開** します。「テストモードのまま運用」は禁止です。
5. このルールはログインだけでは書き込み不可で、次の `staff` 登録済み利用者だけにアクセスを許可します。スタッフは販売のみ、管理者は販売＋取消が可能です。

## 3. スタッフの登録（必須）
1. Firebase → **Authentication** → **Sign-in method** → **メール/パスワード** を有効にします。
2. **Authentication → Users → ユーザーを追加** から、自分・スタッフそれぞれにメールアドレスとパスワードを設定します。各自別アカウントを推奨します。配布時はパスワードを安全に伝えてください。
3. 追加したユーザー行の **UID** をコピーします。
4. **Firestore Database → データ** → 「コレクションを開始」→ コレクションIDを **`staff`** にします。
5. ドキュメントIDを、コピーした **UIDそのもの** にします。
6. フィールドを次のように設定し、保存します。

   | フィールド | 型 | 値の例 |
   |---|---|---|
   | `name` | string | `井口` |
   | `role` | string | `admin` |
   | `active` | boolean | `true` |

   ほかの会計担当者も各UIDでドキュメントを作り、`role` を `cashier` にします。管理者は `admin` を指定します。**初期状態では誰もログインしても操作できません。**
7. `staff`コレクションの作成・変更はFirebaseコンソールから行います。サイトからスタッフが勝手に管理者になることはできません。

## 4. Xserverへの設置
1. Xserverのファイルマネージャを開き、`kiyokasai.info` の公開ディレクトリ（例：`public_html`）にアクセスします。
2. 任意の新規フォルダ（例：`yakisoba-register`）を作成します。
3. `index.html`、`style.css`、`app.js`、入力済みの `firebase-config.js` の **4ファイルを同じフォルダにアップロード**。`firestore.rules` と README はサーバーに置く必要はありません。
4. `https://kiyokasai.info/yakisoba-register/` のようなURLを開きます（フォルダ名によります）。HTTPSを使ってください。
5. Firebase Authentication → **Settings → Authorized domains** にサイトドメイン `kiyokasai.info` を必要に応じて登録します（Firebaseの仕様変更により設定名は変わる場合があります）。
6. 既存の清花祭サイトはそのまま維持し、フォルダを分けて使用できます。**レジのURLを公開サイトのメニューには載せない**ことを推奨します。

## 5. 使い方
1. 端末でURLを開き、スタッフごとのメールアドレス・パスワードでログインします。
2. 「販売日」を確認（11/14または11/15）。**当日の販売日を確認すること**。
3. `+` / `−` または食数のショートカットを使って販売数を選びます（1回1〜20食）。
4. お客様から受け取った現金を「お預かり金額」に入力。ショートカットも使用できます。
5. お釣りを確認して **会計を確定する** を1回タップします。
6. 「会計完了」と表示されたら保存完了。次の注文へ進みます。
7. 「集計」で日別・合計売上を確認します。「履歴」で全端末からの販売記録を表示します。
8. 取消が必要な場合は管理者でログインし、履歴の「取消」を選びます。**現金の返金処理は別途手作業**で行ってください。取消は履歴から消えず、売上集計から除外されます。
9. 「CSV出力」で会計報告用データをダウンロードできます。取消済みの取引も明細に残ります。

## 6. 事前テスト
- 端末Aで1食を入力し、端末Bの集計が増えることを確認。
- 端末Bで2食入力し、端末Aにも反映されることを確認。
- 管理者で1件を取り消し、合計売上が減ることを確認。
- 一般スタッフでは取消ボタンが出ないことを確認。
- CSVファイルがExcelなどで読めることを確認。
- **テスト取引を本番履歴に残さないこと**。テスト用の別Firebaseプロジェクトを使うか、テスト取引を管理者が全て取消したことを確認してください。取消履歴は残るので、会計報告上は別プロジェクトでのテストが最も明確です。

## 7. 注意事項と障害時
- **オンライン専用**。オフライン時は会計の保存を保証しません。通信が復旧するまで紙の集計などに切り替え、復旧後に二重登録しないよう注意してください。
- 保存失敗後は、入力を変えずに「会計を確定する」を再タップすると同じ取引IDで再試行します。既に保存済みなら画面が検知します。ただし**ページ再読み込み後には取引IDを保持しない**ため、履歴を確認してから入力してください。
- 取引数は増えた順にFirestoreの読み込み料金・通信量に影響します。Firebaseには無料枠と利用制限があります。会場ではインターネット接続を確保してください。
- 「残り240食」は目標までの差であり、仕込んだ実在庫ではありません。仕込み数・廃棄・持ち帰りによる在庫は別途管理してください。
- 会計にスタッフ名と日時が記録されます。端末の時刻にかかわらず、Firestoreに記録されたサーバー時刻を主に表示します。
- パスワードとFirebaseコンソールの管理権限は共有しないでください。`firebase-config.js` に管理用秘密鍵やサービスアカウント鍵を入れないでください。
- Firebase側のメール/パスワード利用、Firestore利用には関連するプラン・制限があります。運用前に Firebase コンソールの利用量・課金設定を確認してください。

## 8. 制約
- 現場のスタッフが同時に同じ販売数を入力しても取引は別記録となります。これは正常です。**同じ客の支払いを2台で重複して確定させない**運用が必要です。
- 実在庫の厳密な自動引当や領収書印刷、現金残高との差異チェックには対応していません。
- デモモードはFirebase未設定時のみ使用でき、端末のブラウザ内に保存されます。本番データにはなりません。

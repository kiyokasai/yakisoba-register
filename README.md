# 清花祭2026 焼きそば・ご飯 レジ（画面改良版 v2）

GitHub Pagesで公開し、Firebase Authentication + Firestoreを利用するリアルタイム会計レジです。

**公開先**：https://kiyokasai.github.io/yakisoba-register/

## 変更点

- スマホの画面全体を縦スクロールせずに使えます（履歴は「前へ」「次へ」でページ切替）。
- 「焼きそばの個数・ご飯の個数を指定」→「支払いへ」→「お預かり額を入力」→「会計を確定する」。
- 焼きそばは400円固定、ご飯は管理者が「集計・設定」で価格を登録します。**ご飯価格を勝手に仮定しません。**
- 履歴に販売日時・2商品の個数・金額・スタッフ名。本人の売上または管理者なら「取消」が可能です。取消済みも履歴に残り、売上には加算されません。
- 日別売上、商品別合計食数、目標240食までの進捗、CSV出力。
- 以前のバージョンの焼きそばのみの売上記録も集計・履歴に表示します（互換対応）。
- 保存中の二重押しを防止。通信エラー時には未確認の会計を記憶し、同じ取引IDで保存状態を確認します。

## 既存のGitHubリポジトリを更新（必須）

1. この更新用ZIPを解凍します。既存の `firebase-config.js` は更新用ZIPに含めていないため、接続設定が維持されます。
2. https://github.com/kiyokasai/yakisoba-register を開きます。
3. `Add file → Upload files`（表示されなければ画面上部の「＋」メニュー等）を選択します。
4. 解凍したフォルダの**中身**を全部アップロードします。ZIP自体や外側のフォルダをアップロードしないでください。**既存の `firebase-config.js` は消さず、上書きもしないでください。**
5. 「同じ名前のファイルが存在する」と出たら、変更をコミットして既存ファイルを更新します。
6. `Commit changes` をクリックします。
7. `Settings → Pages` で `Deploy from a branch / main / (root)` に設定済みか確認します。
8. 公開先を開きます：https://kiyokasai.github.io/yakisoba-register/

GitHub Pagesの公開には少し反映時間がかかる場合があります。旧画面のままならブラウザを再読み込みしてください。

**重要**：GitHubに `firestore.rules` をアップロードしても、そのファイルはFirebase上の権限設定に自動反映されません。次のルール更新は必ず別途行います。

## Firebaseを設定（本番共有に必須）

既存のFirebaseプロジェクトを使用する場合は、そのプロジェクトのままでOKです。

1. https://console.firebase.google.com/ でプロジェクトを作る（初回のみ）。
2. Firebaseの「プロジェクトの設定 → マイアプリ → Webアプリ」から `apiKey`, `authDomain`, `projectId`, `appId` を取得します。
3. **リポジトリ内の** `firebase-config.js` をGitHubの編集機能で開き、4つの値を入力してコミットします。APIキーは通常のWebアプリ公開設定ですが、秘密鍵やサービスアカウントのJSONをここへ入れてはいけません。
4. Firebase **Authentication → Sign-in method** で「メール/パスワード」を有効にします。
5. Authentication → Settings → Authorized domains に `kiyokasai.github.io` を追加します（URLや `/yakisoba-register/` は不要）。
6. Firebase **Firestore Database** を作成し、「Rules」に同梱の `firestore.rules` の**全文をコピーして Publish** します。従来版のルールのままだとご飯の会計・価格変更が拒否されます。テストモードのまま公開しないでください。
7. Authentication → Users でスタッフのメールアドレス・パスワードを作成し、各ユーザーの **UID** を控えます。
8. Firestore Database → Data に `staff` コレクションを作成し、**ドキュメントIDをUID** として、下記フィールドを登録します。

| フィールド | 型 | 値の例 |
| --- | --- | --- |
| `name` | string | `会計スタッフ1` |
| `role` | string | `admin` または `cashier` |
| `active` | boolean | `true` |

管理者は最低1人 `admin`、ほかの会計担当を `cashier` にします。スタッフは自分が登録した取引を取り消せます。管理者は全員の取引を取り消せ、ご飯の価格を設定できます。

## 当日の操作

1. スマホで https://kiyokasai.github.io/yakisoba-register/ を開き、スタッフアカウントでログイン。
2. **まず管理者が「集計・設定」でご飯の価格を登録**。1〜1000円の整数を入力して「保存」します。この価格は接続中のすべての端末に共有されます。
3. 「レジ」→ 商品をそれぞれ `＋` / `－` で選ぶ。最初はどちらも0食です。販売日（11/14・15）を確認。
4. 「支払いへ」を押す → お預かり額を入力するか、金額ボタンを押す → お釣りを確認。
5. 「会計を確定する」を押す → 完了画面が出たら「次の会計へ」。完了が確認できるまで重複入力しないでください。
6. 「履歴」で各取引の「取消」を押し、確認画面でもう一度「取消を確定」すると取消済みになります。取消前の金額などの記録は残ります。現金の返金操作は別途行ってください。
7. 「集計・設定」で2日別売上、商品別販売食数を確認し、CSV出力で帳簿を保存できます。

※ 目標240食は**焼きそば**の目標です。ご飯の食数は別に表示します。現物在庫数とは異なります。

## 確認したいこと

- まずデモで「焼きそば2食 → 支払いへ → 1,000円預かり → お釣り200円 → 確定」を試す。
- ご飯の価格をデモ管理者から登録 → ご飯1食の会計を試す。
- 履歴から取消すると、集計金額と食数が減ることを確かめる。
- Firebase設定後、**2台以上のスマホ**で同じ売上がリアルタイムに見えるか、取消した売上が反映されるかを必ず検証する。
- 本番を始める前に、テスト取引を取り消すか、テスト用Firebaseプロジェクトと本番用を分ける。
- 誤操作や通信断に備えて紙でも予備記録をとり、通信が復旧してから履歴を確認する。

### 注意事項

- 今回のZIPにユーザーのFirebase設定値は含まれていません。`firebase-config.js` を入力していない場合はデモのみ動きます。
- デモの記録はブラウザのローカル保存のみであり、本番集計とは無関係です。
- GitHub Pagesは一般公開されます。**顧客情報やパスワードをHTMLやGitHubのファイルに埋め込まない**でください。Firestoreルールでスタッフ以外のデータアクセスを拒否します。
- Firebaseのセキュリティルールは**権限だけでなく金額の整合性**も検査します。ご飯の価格更新中に会計すると「再確認」を促す場合があります。
- 通信障害中はFirebaseへ保存できません。保存結果が未確認の場合は、画面の「保存状態を確認する」を使います。タブを閉じても未確認IDを保持します。
- モバイル画面を優先していますが、極端な拡大表示や非常に小さい画面では端末の表示倍率の調整が必要なことがあります。

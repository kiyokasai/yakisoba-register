# 清花祭2026 焼きそば・ご飯レジ v3

**画面は「レジ」と「履歴」の2つだけ**です。スマホの縦スクロールを不要にし、商品選択から会計確定まで操作できます。

公開予定URL: https://kiyokasai.github.io/yakisoba-register/

## 今回変更した点

- 「集計・設定」のタブをなくし、「レジ」「履歴」の2タブだけにしました。
- レジの手入力の「販売日」をなくし、**会計確定したときに日本時間（Asia/Tokyo）の年月日を自動判定**します。履歴の販売日時も自動記録・表示します。
- Firebaseに保存するときはFirestoreの **サーバー時刻 (`serverTimestamp`)** を保存します。画面の時計・デモでは端末時刻を使います。端末の時刻が不正確な場合は販売日がずれる可能性があるので、端末の「日時を自動設定」をオンにしてください。
- 焼きそば400円/食。ご飯の単価は勝手に決めず、管理者のみ「レジ」の「単価設定」から変更できるようにしました。
- 会計は「食数を選ぶ → 支払いへ → 預かり金額 → 会計を確定する」の順番です。
- 履歴には日時、焼きそば・ご飯の食数、金額、担当者を表示。販売した本人または管理者は取消でき、取消記録も残ります。
- 取消済みの取引は履歴に残りますが、売上としてカウントされません。現金の返金は自動では行われません。
- 同時操作・通信エラーによる二重記録を防ぐために、取引IDの再照会・再試行の仕組みを維持しています。
- 対象の販売日は **2026年11月14日・15日（日本時間）** です。この2日以外の日時は会計確定できません。

## GitHubへ反映する方法

1. `yakisoba-github-v3-update.zip` をダウンロードして解凍します。
2. https://github.com/kiyokasai/yakisoba-register にアクセスします。
3. リポジトリの `Add file → Upload files` を選び、解凍した**中身**をアップロードします。ZIPファイル自体をアップロードしないでください。
4. **`firebase-config.js` は更新用ZIPに含めていません。** リポジトリに既存の接続設定ファイルがある場合はそのまま残してください。
5. `Commit changes` を押します。サイトがすぐに切り替わらないときは、GitHub ActionsでPagesの公開が終わっていることを確認して再読み込みしてください。
6. https://kiyokasai.github.io/yakisoba-register/ を開きます。

`index.html`, `style.css`, `app.js` は3つすべて更新してください。ブラウザの古いキャッシュを読み込まないよう、HTML内の参照に `?v=3.0.0` を付けています。

## Firebaseの準備（未設定の場合）

**デモモードは端末のブラウザ内だけに売上を保存します。スタッフ間で共有するにはFirebaseが必要です。**

1. https://console.firebase.google.com/ でプロジェクトとWebアプリを作成します。
2. Authentication → Sign-in method で「メール/パスワード」を有効にします。
3. Authentication → Settings → Authorized domains に `kiyokasai.github.io` を登録します。
4. Firestore Databaseを作成します。
5. 同梱の `firestore.rules` を Firebase Console の Firestore → Rules へ貼り付け、`Publish` します。**GitHubにアップロードするだけではセキュリティルールは変更されません。**
6. Firebaseのプロジェクト設定から `apiKey`, `authDomain`, `projectId`, `appId` を取得し、GitHubリポジトリ内の `firebase-config.js` の `window.FIREBASE_CONFIG` に入力します。`firebase-config.js` がまだなければ、以下の形で新規作成します。

```javascript
window.FIREBASE_CONFIG = {
  apiKey: "Firebaseから取得したAPIキー",
  authDomain: "Firebaseから取得した認証ドメイン",
  projectId: "Firebaseから取得したプロジェクトID",
  appId: "Firebaseから取得したアプリID"
};
```

7. Authentication → Usersからスタッフ用のメール/パスワードアカウントを作成します。表示される UID を確認します。
8. Firestore Database → Data で `staff` コレクションを作り、**各UIDをドキュメントID**にして、`name` (string、例 `会計1`)、`role` (string、`admin` または `cashier`)、`active` (boolean、`true`) を登録します。`admin` を最低1人指定してください。

FirebaseのWeb APIキー自体は通常公開可能ですが、サービスアカウントの秘密鍵やパスワードをGitHubに保存しないでください。**アクセス制御はFirestoreルールとスタッフ認証で行います。**

## 当日の使い方

1. スマホでサイトを開いてログインします。初期設定がなければ「デモを開始する」で端末内の動作だけ試せます。
2. 初回は管理者がレジの「ご飯」欄にある「単価設定」を開き、ご飯1食の販売価格を保存してください。設定値はFirebase利用時、スタッフの端末間で同期されます。
3. 「レジ」で焼きそばとご飯の数を `＋ / −` ボタンで選び、「支払いへ」を押します。
4. お客様から受け取った現金を入力、または金額ボタンを選択し、お釣りを確認します。
5. 「会計を確定する」を押した時点で、自動的に販売日時が記録されます。完了を確認したら「次の会計へ」で戻ります。
6. 「履歴」で取引時刻と金額を確認できます。誤会計は「取消」→確認画面の「取消を確定」で取消済みになります。履歴を削除せずに残します。
7. 履歴の「全日／11/14／11/15」を切り替えて確認し、件数が多い場合は「前へ」「次へ」でページを切り替えます。

### 注意

- Firebase接続時の正しい登録時刻はサーバー時刻です。ネットワークが切れているときは会計を確定できない場合があります。履歴への保存を確認するまで**同じ会計を改めて入力しないでください**。
- 取消可能な範囲は、レジ担当者が自分で登録した取引、管理者は全員分の取引です。
- 「取消」は売上の記録上の取消であり、実際の返金や現金残高の補正を自動化するものではありません。
- Firestoreのセキュリティルールはv2のデータ構造と互換です。まだ反映していない場合は必ず反映してください。
- スマホで日時を自動設定にしておいてください。会計確定日は端末から自動算出し、Firestoreの登録時刻はサーバーで確定します。
